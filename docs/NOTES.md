## 2026-11-14 (45)  Battle window as cards; the party is what the game says it is
- **Who is in the party**: a record with a name is not enough (the test save's "Nine" has one, and so did the user's: the window showed a Player 4). The game keeps one object per party member at `0x022BBD10 + k * 0x116C0` whose first word is the address of that member's record; `mod_in_party(i)` (nuzlocke.c) looks there. The roster and the Nuzlocke rules use it (Hero ends the run no longer kills a member who isn't in the party; `test_nuzlocke.py` counts members the same way).
- **The battle window is hand-drawn** (`DqixBattlePanel`, the code block before `roster_tick` in mod_cheatwin.c): a card per party member (coloured letter, name, HP and MP bars with numbers) and per enemy (skull, name, HP bar), one big button each (glyph from Segoe UI Symbol + a short word; click = done, gold = a switch that stays on), PARTY left and ENEMIES right (one column when narrow), wheel scrolls, the footer says what the button under the mouse does. HP/MP maxima: an enemy's record has its species' maximum HP at +8 and MP at +0xA (= fld_mondata.bin values 5 and 6); a party member's record has none, so the most seen in this battle is used. Enemy names: `mods/system/bin/monsters.tsv` (catalog.py `write_monsters`: maxhp, maxmp, name for every ordinary species whose pair gives one name), else "Enemy n".
- **Sprites: not done.** Looked at the ROM: `data/bin/icon.nsarc` (a NARC) holds `.spr` files = 4-bit linear bitmaps (header 0x18 bytes, w*h/2 bytes of pixels, 16 BGR555 colours; decoded, they are map and menu icons: sun, barrel, the wing), but face portraits, item icons and monsters were not found: items and menus sit in `.pac` archives with their own layout, monsters are 3D models in `data/pack_lv5/enemy.gp2`. That needs more reverse engineering of the `.pac` format; the window uses drawn glyphs and letters until then.

## 2026-11-14 (44)  Battle cheats window (live roster), one-time cheats only where they make sense
- **Live roster**: `mod_roster` (mod_cheats.c) reads this console's RAM: party member i present when the first byte of the record name at `0x020F54B4 - i * 0x964` is set; a battle is on when the battle copy `+0x58` of the hero is nonzero; enemy n is there when its HP u16 at `0x022A4638 + n * 0xA4` is > 0 (only in a battle). The window polls it every 500 ms (`IDT_ROSTER`) and builds the page again, in place, when who is there changed (an enemy's HP alone does not, except in the battle window, whose titles show it). Entries carry a `who` (`p2`..`p4`, `e1`..`e6`; catalog.py `who_of`, written as `who=`) and are shown only while that member / enemy exists; a section with nobody to show is not drawn. This also trims the Party page of the Cheats window (skill points, jobs, max EXP of members 2-4).
- **Battle cheats window** (menu bar Cheats > Battle cheats..., id 367; a third face of the window: `g_mode` 2, page "Live battle", sections Hero / Player 2-4 / Enemy 1-6 open by default and titled with the name / HP as they are now). The entries are generated by `catalog.py` `battle_entries()` from the game's addresses (same on the EU and USA ROM; the R4 lists have different names and the USA list lacks most of these codes): per member HP and MP never go down (the R4 "HP never decrease" copy code), HP and MP 9999, High tension (+0x6F=1, +0x7C=4), Coup de Grace ready (+0x93=0x98), Invincible (+0x70=0x40, members 2-4 as in the R4 code); per enemy Defeat, HP to 1, MP to 0, sleep (+0x14 = 0x10), poison (+0x14 and +0x22 = 2), stun (0x08), confuse (0x20). The database's own codes that write the same bytes are dropped (`battle_addr_set`). Not offered: "Heal fully" (the record has no maximum to copy: +0x58 is the "actual" HP, the current HP is +0x5C, and the R4 copy code writes the current into the actual).
- **"Do it now" only where it makes sense**: a database code is a one-time cheat only when it is plain writes; a code with copy ops (first nibble A) keeps its switch. A one-time row shows no "One player" and no "once" in its grey line. The battle ones that made no sense as a button on the Cheats page (invincibility, high tension, enemy HP...) moved to the battle window, where they only appear when there is somebody to apply them to.

## 2026-11-13 (21)  Monsters can't flee: fixed at the source
- **Cause found** by watching a headless fight (Guarantomb, `DQIX_MOD_FORCE=3` = every roamer a metal slime, frame dumps + a scratch build that logged function entries and the battle's command list): the monster's turn is built by ov000 `0215767c`, which asks `func_0208a92c` (main, USA `0208a91c`) for the action number; **225 and 917 are the two actions named "Flee"** (action table: 618 records of 60 bytes, id in the low 12 bits of the word at +4, name pointer at +0; found by dumping RAM at the battle).
